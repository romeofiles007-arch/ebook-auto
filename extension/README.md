# Ebook Auto

ส่วนขยาย Chrome ที่รับหัวข้อหนึ่งบรรทัด แล้วขับหน้าเว็บ ChatGPT ทีละเทิร์นจนได้หนังสือครบเล่ม
เรียงพิมพ์ด้วย Typst ในเบราว์เซอร์เอง วัดจำนวนหน้าจากเอกสารจริง วนแก้จนตรงเป้า แล้วส่งออกเป็น PDF
ไม่มีเซิร์ฟเวอร์ ไม่มีค่า API

## ติดตั้ง

1. เปิด `chrome://extensions`
2. เปิด **Developer mode** มุมขวาบน
3. กด **Load unpacked** แล้วเลือกโฟลเดอร์ `extension` นี้
4. กดไอคอนส่วนขยาย จะเปิดแถบข้างขึ้นมา ใช้ปุ่มในนั้นเปิดหน้า Studio

ต้องล็อกอิน chatgpt.com ไว้ก่อนในเบราว์เซอร์เดียวกัน

## ใช้งาน

ในหน้า Studio กรอกหัวข้อ กลุ่มผู้อ่าน จำนวนหน้า ขนาดเล่ม แล้วกดเริ่ม

กดปุ่ม **ทดสอบ Typst** ก่อนใช้งานครั้งแรก จะโหลดไฟล์ wasm ราว 27 MB
แล้วตรวจว่าเรียงพิมพ์ภาษาไทยและนับหน้าได้ถูกต้อง ถ้าข้อนี้ไม่ผ่าน อย่างอื่นไม่ต้องดู

ระบบจะเดินเอง หยุดให้คุณตรวจงานหนึ่งครั้งก่อนสร้างปกและส่งออก

## สองทางในการเขียนเนื้อหา

เลือกได้ในหน้าเริ่มต้นที่หัวข้อ **แหล่งเขียนเนื้อหา** แยกจากแหล่งสร้างภาพโดยสิ้นเชิง

| ทาง | คิดเงิน | ความเร็ว | ข้อจำกัด |
|---|---|---|---|
| `หน้าเว็บ ChatGPT` | ฟรีตามแพ็กเกจที่มีอยู่ | ช้ากว่า ต้องรอหน้าเว็บพิมพ์ทีละตัวอักษร และหน่วง 4–9 วินาทีระหว่างเทิร์นให้ดูเป็นคนใช้งาน | ชนลิมิตข้อความรายสามชั่วโมง · ต้องเปิดแท็บค้าง · ขัดกับเงื่อนไขบริการของ OpenAI |
| `OpenAI API` | จ่ายตาม token ที่ใช้จริง | เร็วกว่ามาก ไม่ต้องหน่วงระหว่างเทิร์นเลย | ต้องมี API key และเครดิต |

ทาง API ใช้ `POST /v1/chat/completions` ซึ่งเป็นรูปแบบที่บริการอื่นจำนวนมากรองรับด้วย
เปลี่ยน `baseUrl` ได้ใน `transport/openai-api.js` จึงชี้ไปที่โมเดลที่รันในเครื่อง
(Ollama, LM Studio) ได้โดยไม่ต้องแก้ส่วนอื่นของระบบ

**ทำไมทาง API ถึงไม่ต้องจำบทสนทนา** — ทุก prompt ในระบบนี้เล่าบริบทของตัวเองครบตั้งแต่แรกอยู่แล้ว
ทั้ง Book Bible สรุปตอนก่อนหน้า และข้อความดิบของเทิร์นที่ต้องเขียนต่อ เพราะทางหน้าเว็บสลับเธรดได้ตลอด
ข้อจำกัดนั้นกลายเป็นข้อได้เปรียบตรงนี้ คือยิงทีละเทิร์นแบบไม่มีสถานะได้เลย
ไม่ต้องสะสมประวัติแชทที่ยิ่งยาวยิ่งแพงและยิ่งทำให้โมเดลไขว้เขว

กด **"ทดสอบโมเดลเขียน"** ก่อนเริ่มเล่มจริง — ตรวจว่าคีย์ใช้ได้และบัญชีมีโมเดลที่เลือกไว้จริง
ถ้าไม่มี จะบอกชื่อโมเดลที่บัญชีนี้เรียกได้มาให้เลือกแทน แทนที่จะไปพังกลางเล่ม

## แชทเดียวทั้งเล่ม

ค่าเริ่มต้นคือ **แชทเดียวทั้งเล่ม** เปิดแชทใหม่ครั้งเดียวตอนเริ่ม จากนั้นอยู่แชทนั้นตลอด
เวอร์ชันก่อนเปิดแชทใหม่ทุกบท ซึ่งพองานขาดตอนกลางคัน แชทที่ค้างอยู่ไม่มีบริบทของบทก่อนหน้า
ทำต่อไม่ได้ เลือกได้สามแบบในหน้าตั้งค่า

| โหมด | ทำอะไร | เหมาะกับ |
|---|---|---|
| `single` | เปิดแชทใหม่ครั้งเดียวตอนเริ่มเล่ม | ค่าเริ่มต้น ทำต่อได้ง่ายที่สุด |
| `reuse` | ไม่เปิดแชทใหม่เลย ใช้แชทที่เปิดค้างอยู่ | อยากคุมเองว่าจะให้เขียนในแชทไหน |
| `chapter` | เปิดแชทใหม่ทุกบท | เล่มหนามากจนแชทเดียวเริ่มช้า |

## ภาพในเล่มและปก

การเขียนเนื้อหากับการสร้างภาพ **แยกขาดจากกัน** โดยตั้งใจ เพราะบัญชี ChatGPT แบบฟรี
เขียนข้อความได้แต่สร้างภาพไม่ได้ ระบบจึงออกแบบให้เขียนเนื้อหาด้วยบัญชีไหนก็ได้
แล้วไปหาไฟล์ภาพมาจากที่ไหนก็ได้

ทั้งปกและภาพในเล่มเลือกได้สามโหมดเหมือนกัน

| โหมด | ทำอะไร | เหมาะกับ |
|---|---|---|
| `prompt` | ระบบเขียน prompt + บอกขนาดพิกเซลที่ต้องได้ แล้วให้คุณไปสร้างเอง | ค่าเริ่มต้น ใช้ได้กับบัญชีฟรี |
| `upload` | คุณมีไฟล์อยู่แล้ว อัปโหลดเข้ามา | มีภาพของตัวเอง หรือจ้างคนวาด |
| `auto` | ให้ ChatGPT สร้างในแท็บเดียวกัน | บัญชีรายเดือนที่สร้างภาพได้ |

ขั้น "วางแผนภาพประกอบ" เป็นเทิร์นข้อความล้วน จึงทำงานได้แม้บัญชีสร้างภาพไม่ได้
ผลที่ได้คือตำแหน่ง คำบรรยาย และ prompt ของทุกภาพ เก็บไว้ครบ
กดปุ่มส่งออกได้เป็นไฟล์ `figure-prompts.md` ที่บอกทั้ง prompt ชื่อไฟล์ที่ต้องเซฟ
และขนาดพิกเซลขั้นต่ำของแต่ละรูป เอาไปเปิดในบัญชีที่สร้างภาพได้แล้วทำทีละรูป

### รูปแบบภาพในเล่ม

| แบบ | หมายเหตุ |
|---|---|
| **กล่องสรุป** | ให้ Typst วาดเอง ไม่ต้องสร้างภาพ คมทุกความละเอียด — ค่าเริ่มต้น |
| ลายเส้นขาวดำ | คมที่สุดเมื่อพิมพ์ขาวดำ ปลอดภัยที่สุด |
| ไดอะแกรมเรียบ | อธิบายขั้นตอน กระบวนการ ความสัมพันธ์ |
| สเก็ตช์มือวาด | โทนเป็นกันเอง |
| ริโซกราฟมีพื้นผิว | มีบุคลิก |
| ไอคอนสัญลักษณ์ | หัวบทหรือจุดสังเกต |
| ภาพถ่ายขาวดำ | เมื่อต้องการความสมจริง |

กล่องสรุปเป็นค่าเริ่มต้นเพราะ "ภาพ" ในหนังสือ non-fiction จำนวนมากจริง ๆ แล้วเป็น
ขั้นตอน ตารางเปรียบเทียบ หรือข้อควรระวัง ซึ่งจัดเป็นกล่องอ่านง่ายกว่าและคมกว่าภาพวาด

ในต้นฉบับ ภาพเขียนเป็น `![คำบรรยาย](fig:ชื่อไฟล์ 80%)` และกล่องเขียนเป็นบล็อก `:::box`
ทั้งคู่ย้ายตำแหน่งได้ด้วยการตัดแปะข้อความในโหมดแก้ไข ถ้ายังไม่ได้ใส่ไฟล์ภาพ
ระบบจะวาดกรอบว่างที่กินพื้นที่เท่าของจริง จำนวนหน้าที่นับได้จึงไม่เพี้ยนเมื่อใส่ภาพทีหลัง

ภาพที่อัปโหลดจะถูกย่อและแปลงเป็นโทนเทาให้อัตโนมัติ (ยกเว้นปกและเล่มที่พิมพ์สี)
พร้อมบอก dpi จริงที่ขนาดพิมพ์นั้น ถ้าต่ำกว่า 300 จะเตือนให้เห็น

## แก้ในเวิร์ดก่อนทำ PDF

Typst ให้งานพิมพ์ที่คุมได้แม่น แต่แก้ยากสำหรับคนที่ไม่เขียนโค้ด วงจรที่ใช้ได้จริงคือ

```
ระบบเขียน → ส่งออก .docx → แก้ในเวิร์ด → นำกลับเข้าระบบ → Typst ทำ PDF พร้อมพิมพ์
```

ไฟล์ .docx ใช้ขนาดหน้าและขอบตรงกับที่ตั้งไว้ หัวข้อระดับ 2 เขียนเป็น `1.2 ชื่อตอน`
เลขตอนนั้นคือสิ่งที่ใช้จับคู่กลับตอนนำเข้า อย่าลบทิ้ง ถ้าลบไปแล้วระบบจะเดาจากลำดับแทน
ตอนนำเข้าจะแสดงให้ดูก่อนว่าจะทับตอนไหนบ้าง เปลี่ยนไปกี่ตัวอักษร แล้วค่อยยืนยัน
ของเดิมถูกเก็บไว้ย้อนกลับได้เสมอ

**ตัวเลขจำนวนหน้าที่เชื่อถือได้ยังต้องมาจาก Typst** เพราะเวิร์ดจัดบรรทัดไม่เหมือนกัน
หลังนำเข้าให้กดนับหน้าใหม่ทุกครั้ง

## สามเรื่องที่ต้องรู้ก่อนแก้โค้ด

**สมองต้องอยู่ในแท็บ ไม่ใช่ service worker** — MV3 ฆ่า service worker เมื่อไม่มีงานราว 30 วินาที
งานผลิตหนังสือใช้เวลาเป็นชั่วโมงและมีช่วงรอนาน ๆ ระหว่างเทิร์น ถ้าวางตัวควบคุมไว้ที่นั่น
งานจะตายกลางทางแบบสุ่มและหาสาเหตุยากมาก

**Typst ต้องรันในห้อง sandbox** — ไลบรารี typst.ts มีบรรทัด `new Function('m','return import(m)')`
อยู่ในเส้นทางโหลดฟอนต์ ซึ่ง CSP ของหน้า extension ปกติห้ามไว้ (`wasm-unsafe-eval` อนุญาตแค่
WebAssembly ไม่ได้อนุญาต `new Function`) หน้าที่ประกาศใน `manifest.sandbox` จะได้ CSP ที่ผ่อนคลายกว่า
แลกกับการเรียก `chrome.*` ไม่ได้ ทุกอย่างจึงคุยผ่าน postMessage และไบต์ทั้งหมดส่งเข้ามาจากหน้าแม่

**คำตอบต้องมาในบล็อกโค้ดเดียว** — เราไม่อ่าน HTML ที่ ChatGPT เรนเดอร์แล้วแปลงกลับเป็น markdown
เพราะจะเสียโครงสร้างและพังทุกครั้งที่หน้าเว็บเปลี่ยน แต่บังคับให้โมเดลตอบในบล็อกโค้ด แล้วอ่าน
`textContent` ของ `pre code` ตรง ๆ ประกบด้วย sentinel `<<<SEC 1.2 BEGIN/END>>>`
เพื่อตรวจว่าได้ของถูกตอนและไม่ถูกตัด

## การเรียงพิมพ์ภาษาไทย

ไทยไม่เว้นวรรคระหว่างคำ เครื่องเรียงพิมพ์จึงไม่รู้ว่าตัดบรรทัดตรงไหนได้
ระบบตัดคำเองแล้วแทรก ZWSP (U+200B) ก่อนป้อนเข้า Typst แต่แค่นั้นไม่พอ
เพราะตัวตัดคำของเบราว์เซอร์กับของ Node ให้ผลไม่เหมือนกันเสมอไป
`core/thai.js` จึงมีด่านตรวจทุกจุดตัดด้วยกฎภาษาไทยตรง ๆ ซึ่งได้ผลเหมือนกันทุกที่

| กฎ | กันอะไร |
|---|---|
| ห้ามตัดหน้าสระ/วรรณยุกต์ | กัน `เฉพาะวันท` / `ี่ธุรกิจ` — สระลอยไปขึ้นบรรทัดใหม่ตัวเดียว |
| ห้ามจบบรรทัดด้วยสระหน้า เ แ โ ใ ไ | สระหน้าต้องอยู่ติดพยัญชนะที่ตามมา |
| ห้ามตัดหน้า ๆ และ ฯ | ไม้ยมกกับไปยาลน้อยต้องเกาะคำข้างหน้า |
| ช่องว่างคั่นวรรค → ระยะแบบ weak | กันช่องว่างไปโผล่หน้าบรรทัดใหม่ เห็นเป็นบรรทัดเยื้องผิด ๆ |

และตั้ง `linebreaks: "optimized"` ให้ Typst ไล่หาจุดตัดที่ดีที่สุดของทั้งย่อหน้า
ทำให้ขอบขวาสม่ำเสมอขึ้นมากโดยไม่ต้องจัดชิดสองข้าง ซึ่งภาษาไทยทำแล้วเกิดช่องว่างพาดกลางหน้า
เพราะไม่มียัติภังค์ให้เกลี่ย

ทุกกฎมีชุดทดสอบ และตรวจด้วยการเรนเดอร์จริงพร้อมเส้นไกด์ที่ขอบบล็อกข้อความ
ไม่ใช่ดูด้วยตาเปล่า

### ข้อจำกัดที่แก้ไม่ได้: คัดลอกข้อความไทยจาก PDF ไม่ได้

Typst ฝังฟอนต์แบบ Identity-H และกำหนดตำแหน่ง glyph ไว้ตายตัวในไฟล์
**ภาพที่เห็นและที่พิมพ์ออกมาจึงถูกต้องเหมือนกันทุกเครื่องทุกโปรแกรม รวมทั้ง iPhone**
ไม่มีการแทนฟอนต์หรือจัดรูปใหม่ตอนเปิดไฟล์

แต่ตารางแปลง glyph กลับเป็นตัวอักษร (ToUnicode) ของ Typst ยังไม่ถูกต้องสำหรับภาษาไทย
ทดสอบแล้วเพี้ยนทั้งรุ่น 0.13 และ 0.14 และเพี้ยนเหมือนกันทั้ง Sarabun และ IBM Plex Sans Thai
จึงไม่ใช่เรื่องฟอนต์ ตัวอย่างที่ได้เมื่อคัดลอกออกมา

```
ต้นฉบับ   ทดสอบการคัดลอกข้อความภาษาไทย ราคา 1,200 บาทต่อเดือน
คัดลอกได้  ทดสอบการคั ดลอกข้ อคั วามภาษาไทย ราคั า 1,200 บาท ต่อเดอน
```

กระทบเฉพาะสามอย่าง: คัดลอกข้อความจากไฟล์ · ค้นหาคำในไฟล์ · โปรแกรมอ่านออกเสียง
ไม่กระทบการอ่านและการพิมพ์ ถ้าผู้อ่านต้องค้นหาข้อความได้ ให้แจก EPUB ควบคู่ไปด้วย
ซึ่งเป็นข้อความจริงทั้งหมด preflight จะเตือนเรื่องนี้ทุกครั้งที่เล่มเป็นภาษาไทย

## ข้อจำกัด

- ทำขนานไม่ได้ บัญชีเดียว และแต่ละตอนต้องรู้ว่าตอนก่อนหน้าเขียนอะไร
- ลิมิตข้อความของแพ็กเกจ ChatGPT คือเพดานจริงของระบบ ชนแล้วระบบหยุดสนิทและรอให้คนสั่งทำต่อ
  ไม่ลองใหม่เองเป็นรอบ ๆ (เวอร์ชันแรกลองเองทุก 30 นาที จึงวิ่งกินโควตาทั้งวัน)
- ไม่มีเพดานจำนวนข้อความ ระบบใช้เท่าที่เนื้อหาต้องการและเดินต่อจนจบงาน
- ตอนหนึ่งไม่ควรเกินราว 8,000 อักษร เพราะคำตอบเทิร์นเดียวยาวได้จำกัด
- ต้องเปิดเครื่องและเปิดแท็บค้างไว้ ไม่ใช่บริการบนคลาวด์
- ภาพจาก ChatGPT ราว 1024×1536 ซึ่งเป็นเพียง ~170 dpi บนปก 6×9 นิ้ว ต่ำกว่าเกณฑ์งานพิมพ์
  ให้ออกแบบปกให้ภาพเป็นส่วนหนึ่ง ที่เหลือให้ Typst วาดเป็นเวกเตอร์
- งานทั้งหมดอยู่ใน IndexedDB ถ้าล้างข้อมูลเบราว์เซอร์ งานหาย ให้ส่งออก `project.json` เก็บไว้

การใช้สคริปต์ขับหน้าเว็บ ChatGPT ขัดกับเงื่อนไขการใช้บริการของ OpenAI ที่ให้เข้าถึงแบบอัตโนมัติ
ผ่าน API เท่านั้น มีความเสี่ยงต่อบัญชี ชั้น `transport/` ออกแบบให้สลับไปใช้ API หรือโมเดลโลคัลได้
โดยไม่ต้องรื้อระบบ และ `transport/fake.js` ใช้ทดสอบลูปนับหน้าได้โดยไม่ต้องยิง ChatGPT เลย
