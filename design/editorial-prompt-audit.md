# ผลตรวจ prompt และการส่งต่องานหนังสือ

วันที่ 7 กันยายน 2026

## ขอบเขตและหลักฐาน

ตรวจโค้ด prompt ฝ่ายวางโครง เขียน ตรวจ แก้ต้นฉบับ ขยายความยาว และข้อมูลความจำของเล่ม พร้อมอ่านตัวอย่างตอน 4.2–4.3 และผลตรวจบทจากประวัติ ChatGPT ของหนังสือ «พูดให้ขำขึ้น โดยไม่ต้องเกิดมาเป็นคนตลก» ข้อสังเกตจากตัวอย่างไม่ใช่ผลประเมินต้นฉบับทั้งเล่ม

ตัวอย่างที่พบ: ตอน 4.3 มีตารางแผนฝึก ตามด้วยย่อหน้ารวมจำนวนชิ้นงาน และกล่องรวมชิ้นงานอีกครั้ง ตอน 4.2 และ 4.3 ย้ำการเลือกแก้หนึ่งจุดหลายตำแหน่ง แม้การอ้างหลักเดิมเพื่อใช้งานขั้นต่อไปทำได้ แต่แต่ละตำแหน่งต้องเพิ่มเกณฑ์ตัดสินหรือการสาธิต ผลตรวจเดิมจับความซ้ำในกล่องและตัวเลขไม่สอดคล้องได้ จึงไม่ใช่ว่าฝ่ายตรวจไม่ทำงานเลย

## สิ่งที่แก้ในโค้ด

| แผนก | ปัญหาที่พบ | การปรับ |
| --- | --- | --- |
| ตั้งชื่อ/วางแนวทาง | แรงกดดันให้ดูคมและแตกต่างอาจนำหน้าคุณประโยชน์จริง | ระบุผู้อ่าน ปัญหา และวิธีเฉพาะของเล่ม ไม่อ้างผลทางการขายที่ไม่มีข้อมูล |
| วางสารบัญ | บังคับรูปแบบและข้อสรุปเด็ดขาด เสี่ยงแบ่งหัวข้อที่ทำหน้าที่ซ้ำ | แต่ละตอนมีคำถาม ข้อเสนอ เนื้อหาที่ต้องอธิบาย และขอบเขตที่เว้นให้ตอนอื่น |
| สร้างเสียงผู้เขียน | การ์ดอัตโนมัติเปิดช่องให้แต่งอาชีพและประสบการณ์ | สร้างแนวทางการเล่าแทนประวัติ และไม่ใช้ประวัติแต่งจากการ์ดเก่า |
| เขียนเนื้อหา | สูตรการเดินเรื่องและคำคมซ้ำ พร้อมข้อห้ามทางภาษาที่ขัดกับการอธิบาย | ใช้เกณฑ์ร่วม: ทุกย่อหน้าเพิ่มความเข้าใจ จบเมื่อคำถามได้รับคำตอบ ใช้ตัวอย่างและรูปแบบตามความจำเป็น |
| เขียนแบบรายการ | เปลี่ยนถ้อยคำแต่ใจความเดิมได้ง่าย | ตรวจความซ้ำระดับความหมาย และไม่บังคับจุดหักหรือคำสั่งทุกข้อ |
| ตรวจต้นฉบับ | เกณฑ์สำนวนอาจแย่งความสำคัญจากเหตุผลและเนื้อหาซ้ำ | ตรวจคุณประโยชน์ ความซ้ำ เหตุผล หลักฐาน และความต่อเนื่อง พร้อมข้อความจริงและวิธีแก้เฉพาะจุด |
| แก้ต้นฉบับ | การรักษาความยาวและรูปแบบอาจขัดกับการตัดส่วนซ้ำ | ยอมให้สั้นลง ตัด/รวมกล่องซ้ำได้ รักษารหัสภาพ และส่งสรุปตอนที่แก้แล้วกลับเข้าความจำ |
| ปรับจำนวนหน้า | ตอนสั้นถูกส่งขยายแม้ตอบโจทย์ครบ | โหมดปกติข้ามการขยายเมื่อมี short_reason; โหมด strict ยังยึดเป้าความยาว แต่ prompt ห้ามเติมเนื้อหาวน |
| ส่งต่องาน/ความจำ | สรุปเดียวจากงานแบบชุดถูกใส่ให้หลายตอน ทำให้บริบทปนกัน | สารคดีส่ง META แยกตอนและรับเข้าความจำตามรหัส; งานต่อและงานกู้คืนได้รับบริบทเดิม |

เกณฑ์ร่วมอยู่ใน `extension/core/editorial.js` ส่วน `prompts.js` เรียกใช้เกณฑ์เดียวกัน และ `machine.js` จัดการข้อมูลส่งต่อ นิยายยังใช้คำสั่งฉากและ canon เดิม ไม่ถูกเปลี่ยนเป็นเกณฑ์การเขียนสารคดี

## ภาพประกอบ: ผลตรวจจากงานก่อนหน้า

ในบทสนทนาที่ตรวจพบภาพที่สร้างแล้ว 4 ภาพ แต่ตัวอ่านคำตอบใช้ selector ที่ไม่ตรงกับหน้าปัจจุบัน และมี prompt ซ้ำ จึงมีปัญหาในช่วงตรวจจับคำตอบ/ส่งต่องาน ไม่อาจสรุปว่า ChatGPT ไม่สร้างภาพทุกครั้ง แก้ตัวอ่านคำตอบ การตรวจช่องพิมพ์ก่อนส่ง และผูกการเก็บภาพกับแท็บและรอบงานแล้ว

ยังไม่ได้ยืนยันการสร้างภาพ → เก็บไฟล์ → ใส่เล่ม → ส่งออก ผ่าน Studio จริงครบเส้นทาง เพราะเครื่องมือเปิดหน้า extension Studio ถูกนโยบายเครื่องมือบล็อกไว้ การทดสอบโค้ดไม่ทดแทนการตรวจไฟล์เล่มปลายทาง

## การตรวจสอบและข้อจำกัด

- ชุดทดสอบ editorial 8 รายการ ตรวจรูปแบบ prompt การแยก META ผ่านตัวอ่านจริง บริบทงานต่อ การแก้ และขอบเขตนิยาย
- ชุดทดสอบ image flow 6 รายการ รวมกับ editorial เป็น 14 รายการ
- ตรวจ syntax และสัญญา UI เพิ่มเติม
- ยังไม่ได้ให้โมเดลสร้างต้นฉบับใหม่ด้วย prompt ชุดนี้ และยังไม่ได้แก้เนื้อหาในหนังสือเดิม

ก่อนผลิตทั้งเล่ม ควรโหลด extension และแท็บที่เกี่ยวข้องใหม่ แล้วทดลองหนึ่งบทที่มี 2–3 ตอนติดกัน ตรวจว่าทุกตอนเพิ่มความเข้าใจ ตัวอย่างสาธิตสิ่งที่สอนได้จริง และการแก้ไม่สร้างส่วนซ้ำกลับมา จากนั้นทดลองภาพหนึ่งภาพจนเห็นอยู่ในไฟล์ส่งออกจริง คุณภาพต้นฉบับและโอกาสขายต้องประเมินจากผลงานและผู้อ่าน ไม่สามารถรับประกันจาก prompt หรือการทดสอบโค้ดได้
